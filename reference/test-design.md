# 用例设计规范

## 4 种设计方法

| 方法 | 怎么用 | 示例 |
|------|--------|------|
| 等价类划分 | 输入分有效/无效组，每组取一个代表 | 邮箱：有效(a@b.com)、无效(缺@、空) |
| 边界值分析 | 边界取 3 点：等于、刚超、刚不到 | 名称 1-50 → 测 0/1/50/51 |
| 场景法 | 业务流程串联：主流程+分支+异常 | 注册→登录→查→改→删 |
| 错误推测法 | 猜容易出错的地方 | null、空数组、并发、重复提交 |

## 9 个覆盖维度

功能正向 / 数据完整性 / 认证权限 / 参数校验 / 边界值 / 业务规则 / 安全性 / CRUD链式 / 错误格式一致

认证权限维度只适用于契约要求认证的接口。明确无需认证的 API 不得臆造 401/403；用数据完整性或业务规则场景补足覆盖。

## 错误推测清单

null / 空字符串 / 纯空格 / 类型错配 / 空数组 / 超长文本 / 特殊字符(emoji/换行) / 重复提交 / 并发 / 空body / Content-Type错

## 代码 3 要素

```python
@allure.title("接口功能 - 具体验证点")   # ① 中文标题
def test_xxx(self):
    """描述测什么、为什么。"""             # ② docstring
    resp = allure_request(..., expected="具体预期")  # ③ 预期结果
```

参数化用 `{参数名}` 自动替换。

## 编写红线

1. 用例文件固定保存为 `<PROJECT_DIR>/tests/test_<模块名>.py`
2. 禁止直接调用 `requests`/`httpx` 或 mock 传输层；GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS 都必须通过 `auth_session` 或 `allure_request`
3. 每次 HTTP 调用必须传中文 `expected="..."`
4. 每个用例必须通过 `auth_session`、`allure_request` 或项目内基于它们的公共助手发起真实请求；只含 `assert True`、mock 或文字说明的空壳测试不能交付
5. 每个用例至少包含一个由模型按契约写出的真实判断；框架不决定具体状态码、字段、类型或业务规则
6. 一个 CRUD/工作流用例可以有准备、主验证和清理请求；辅助请求同样经过统一封装，模型按主验证接口统计归属，不增加只为机器审计服务的 marker
7. 发起有副作用、并发、支付或权限变更测试前，必须已有用户确认的测试环境/授权和清理策略；未确认不得执行

## 断言写法

实际探测用于发现文档差异；正式断言以用户确认的契约为准。契约规定单一状态码、字段类型或业务错误码时精确断言；只有契约明确允许多个结果时才使用集合断言并注明原因。禁止仅为全绿而放宽断言。

## 认证、参数化与时间窗口

- 认证成功用例使用 `auth_session`；未认证拒绝用例使用 `allure_request` + `base_url`，确保没有复用带凭据 session。接口无需认证时不臆造认证失败用例。
- 同一接口、请求步骤和断言结构一致的纯数据变体优先使用 `pytest.mark.parametrize`。每组有中文 `id`，输入、中文 `expected` 和断言值均按契约确定；契约预期相同时可以共用。
- 正向、鉴权、链式等不同业务语义分开编写；前置条件或断言结构不同时不强行合并，也不为合并用例而放宽断言。
- 限流或时间窗口测试以契约规定的窗口、阈值、响应码和 `Retry-After` 语义判断；需要等待时采用最小必要等待，不把“成功或限流都算通过”作为通用断言。

## 公共助手与薄用例

- 请求步骤或断言结构重复明显时才抽取项目内公共助手；具体业务预期由各用例按契约传入，接口特有的业务判断保留在用例中。
- 助手发请求时仍使用 `auth_session` 或 `allure_request` 并传中文 `expected`；未认证请求使用 `allure_request`，`base_url` 只提供地址。
- 各接口和场景保留独立 pytest node，中文 `allure.title` 含接口与场景；不为省代码把互不相关的接口合成一个测试。CRUD/工作流用例仍按主验证接口计数。

用例数量以 `pytest --collect-only -q` 展开后的测试 node 为准。参数化的每个实例计为一条；模型根据测试代码整理每个接口的 node 数，合计必须等于 pytest collected 总数。
